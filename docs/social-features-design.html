Overview

This document specifies the design and implementation of four interconnected social features that will increase player retention and engagement:

Friend System

Players can send friend requests, accept/decline invitations, view their friends list, and remove friends. Online status indicators show which friends are currently active.

Challenge System

Players can challenge specific friends to matches. Challenges support game mode selection (mode1/mode2) and can be accepted, declined, or expire after 5 minutes.

Private Matches

Players can create shareable match links that friends can join directly, bypassing the matchmaking queue. Supports custom game modes and spectator access.

Recent Opponents

Automatically tracks the last 20 opponents for each player, with quick actions to add as friend or challenge to rematch.

REST API Endpoints

Friend System

POST /friends/request
Send a friend request to another player
{
  "addresseeId": "player-uuid"
}
GET /friends
Get current player's friends list (status=ACCEPTED only)
GET /friends/requests
Get pending friend requests (incoming and outgoing)
POST /friends/respond
Accept or decline a friend request
{
  "friendshipId": "friendship-uuid",
  "action": "ACCEPT" | "DECLINE"
}
DELETE /friends/:friendshipId
Remove a friend or cancel a pending request
POST /friends/block
Block a player (prevents friend requests and challenges)
{
  "blockedId": "player-uuid"
}

Challenge System

POST /challenges/create
Challenge a friend to a match
{
  "challengedId": "player-uuid",
  "mode": 1 | 2
}
GET /challenges
Get active challenges (sent and received, status=PENDING)
POST /challenges/respond
Accept or decline a challenge
{
  "challengeId": "challenge-uuid",
  "action": "ACCEPT" | "DECLINE"
}
DELETE /challenges/:challengeId
Cancel a pending challenge (challenger only)

Private Matches

POST /private-matches/create
Create a private match with shareable link
{
  "mode": 1 | 2
}

Returns: { code: "ABC123", url: "/join/ABC123" }

POST /private-matches/join/:code
Join a private match using the 6-character code
GET /private-matches/:code
Get private match details (for validation before joining)

Recent Opponents

GET /recent-opponents
Get last 20 unique opponents with match details

Returns array sorted by lastPlayedAt DESC, includes opponent profile and match outcome

Feature Specifications

Friend System

Requirements

  • Bidirectional friendship (both players must be friends to see each other)
  • Friend request must be sent → pending → accepted by addressee
  • Players can only send one friend request per addressee at a time
  • Friend limit: 200 friends per player
  • Anonymous players can have friends, but cannot send requests to OAuth players
  • Online status indicators (green dot) for friends currently connected via WebSocket
  • Display friend count badge in navbar

Business Rules

  • Cannot send friend request to yourself
  • Cannot send friend request if already friends or request is pending
  • Cannot send friend request to blocked player
  • Removing a friend deletes the Friendship record (not soft delete)
  • Friend requests never expire (player must manually decline)
  • When player blocks another, all existing friendships and pending requests are deleted

Challenge System

Requirements

  • Can only challenge players who are friends (status=ACCEPTED)
  • Challenge includes game mode selection (mode1 or mode2)
  • Challenges expire after 5 minutes if not accepted
  • Challenger can cancel challenge before it's accepted
  • Challenged player receives real-time notification via WebSocket
  • Accepting creates match immediately (bypasses matchmaking queue)
  • Players can have max 3 pending outgoing challenges at once
  • Show challenge notification toast with accept/decline buttons

Business Rules

  • Cannot challenge offline friends (must check online status first)
  • Cannot challenge friend who is currently in a match
  • Cannot challenge same friend if challenge is already pending
  • Accepting challenge removes both players from any matchmaking queues
  • Created match is always unranked (ranked matches only via queue)
  • Background job expires challenges every 30 seconds (check expiresAt)

Private Matches

Requirements

  • Creator selects game mode when creating link
  • Generate 6-character alphanumeric code (e.g., "A3X9K2")
  • Link format: https://yourdomain.com/join/A3X9K2
  • Links expire after 15 minutes of creation
  • Only one player can join (first come first serve)
  • Creator can share link via copy button or social share
  • Display "Waiting for opponent..." UI while link is active
  • Allow spectators to join via same link after match starts

Business Rules

  • Private matches are always unranked
  • Cannot join your own private match link
  • Anonymous players can create and join private matches
  • Creator can cancel link before opponent joins (transitions to EXPIRED)
  • Once match starts, link remains valid for spectators only
  • Background job expires links every 60 seconds (check expiresAt)

Recent Opponents

Requirements

  • Automatically track last 20 unique opponents per player
  • Update after each match completion (not when match starts)
  • Show opponent profile, rating, last played timestamp, match outcome
  • Quick actions: "Add Friend" button, "Challenge" button
  • Display in sidebar or dedicated "Recent" tab
  • Sort by lastPlayedAt DESC (most recent first)

Business Rules

  • Bot opponents are NOT tracked (only real players)
  • Playing same opponent multiple times updates lastPlayedAt (no duplicate entries)
  • Oldest opponent is removed when 21st unique opponent is added
  • Practice matches and private matches both count toward recent opponents
  • If opponent deletes account, show "[Deleted User]" placeholder

UX Flows

Friend Request Flow

1
Player A searches for Player B
Via leaderboard, recent opponents, or dedicated player search
2
Player A clicks "Add Friend" button
POST /friends/request with Player B's ID
3
Player B receives notification
WebSocket FRIEND_REQUEST_RECEIVED + red badge on friends icon
4
Player B reviews request in friends panel
Shows Player A's profile, rating, win rate, mutual friends count
5
Player B accepts or declines
POST /friends/respond → status updates to ACCEPTED or DECLINED
6
Player A receives acceptance notification
WebSocket FRIEND_REQUEST_ACCEPTED → both players now see each other in friends list

Challenge Flow

1
Player A opens friends list
Green dot indicates Player B is online and available
2
Player A clicks "Challenge" on Player B
Modal opens: select game mode (mode1 or mode2) + confirm
3
Challenge sent
POST /challenges/create → Challenge record created with PENDING status
4
Player B receives toast notification
WebSocket CHALLENGE_RECEIVED → "PlayerA challenged you to Mode 1!" with Accept/Decline buttons
5
Player B clicks Accept
POST /challenges/respond → Match created immediately, both players redirected
6
Match starts
WebSocket MATCH_FOUND → both players load game board, challenge status → ACCEPTED

Private Match Flow

1
Player A clicks "Create Private Match"
Modal opens: select game mode + generate link
2
Link generated
POST /private-matches/create → returns code "A3X9K2" and full URL
3
Player A shares link
Copy button or share to Discord/Slack/Twitter. Player A sees "Waiting for opponent..." screen
4
Player B opens link
GET /private-matches/A3X9K2 → validates code, shows creator info + mode
5
Player B clicks "Join Match"
POST /private-matches/join/A3X9K2 → creates match, assigns X/O, updates status to ACTIVE
6
Match starts
Both players redirected to game board via WebSocket MATCH_FOUND

Security Considerations

Authentication & Authorization

  • All endpoints require valid session token (middleware: requireAuth)
  • Players can only access their own friends list and requests
  • Players can only respond to challenges addressed to them
  • Players can only cancel their own challenges and private matches
  • Blocked players cannot send requests or challenges (check both directions)

Rate Limiting

  • Friend requests: 10 per hour per player
  • Challenges: 20 per hour per player
  • Private match creation: 30 per hour per player
  • Implement using Redis with sliding window counter
  • Return 429 Too Many Requests with Retry-After header

Input Validation

  • Validate all player IDs are valid UUIDs
  • Validate mode is 1 or 2 only
  • Validate private match codes are 6 alphanumeric chars
  • Sanitize all user-facing strings (displayName, username)
  • Prevent SQL injection via Prisma parameterized queries

Privacy & Spam Prevention

  • Players can block others to prevent all interactions
  • Anonymous players cannot see OAuth player emails
  • Private match codes are cryptographically random (use crypto.randomBytes)
  • Challenge and friend request notifications can be muted (user preference)
  • Prevent friend request spam: cannot resend to same player for 24h after decline

Data Retention

  • Expired challenges: soft delete (keep for analytics), purge after 30 days
  • Expired private matches: soft delete, purge after 7 days
  • Declined friend requests: delete immediately (no history)
  • Removed friendships: hard delete (GDPR compliance)
  • Recent opponents: keep indefinitely (only 20 per player)
